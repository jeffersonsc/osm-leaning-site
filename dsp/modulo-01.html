§ 01

O problema real.

Você vai escrever um plugin que processa a voz do pastor. Antes de escrever uma única linha de DSP, você precisa responder: o que exatamente entra na tua função?

A resposta é: uma sequência de números. Milhares deles por segundo. Cada número representa a pressão do ar em um instante específico, capturada pelo microfone e convertida pela interface de áudio.

Se você não entende como o som virou esses números — quantos números por segundo, qual o tamanho de cada um, qual a faixa de valores válida — você vai escrever código que parece funcionar mas produz áudio com distorção, ruído, ou silêncio. E não vai saber por quê.

Este módulo resolve isso. Ao fim, você olha para um array [f32] no seu código Rust e sabe exatamente o que cada posição significa no mundo físico.

Atalho mental

Áudio digital = fotografar o som muito rápido. Cada foto é uma amostra. Muitas amostras por segundo formam a ilusão de continuidade — mesmo princípio de cinema, só que em vez de 24 fotos por segundo, são 48.000.

§ 02

Amostragem, sem fórmula.

O som é uma onda de pressão que varia no tempo. Contínua. Fluida. Um microfone captura essa onda como uma tensão elétrica que varia do mesmo jeito — contínua também. Isso é áudio analógico.

Computador não lida com "contínuo". Computador lida com números discretos. Então a interface de áudio faz o seguinte: ela mede a tensão elétrica vindo do microfone em intervalos regulares, extremamente rápidos, e anota o valor de cada medição.

Cada medição é uma amostra (em inglês, sample). A sequência dessas amostras é o áudio digital.

Onda analógica (laranja pálido) e suas amostras discretas (pontos brilhantes). Cada ponto é um número que vai para a memória.

A pergunta natural: com que frequência a interface mede? Essa é a sample rate (taxa de amostragem) — e é aqui que começam as decisões importantes.

§ 03

Sample rate: por que 48 mil.

Sample rate é quantas amostras por segundo. Unidade: hertz (Hz) ou kilohertz (kHz).

  • 44.100 Hz (44.1 kHz) — padrão do CD, herança dos anos 80
  • 48.000 Hz (48 kHz) — padrão de vídeo, broadcast, áudio profissional moderno
  • 96.000 Hz (96 kHz) — estúdios high-end, overkill para live
  • 192.000 Hz — mastering, arquivamento, placebo audiófilo

De onde vem esses números?

Tem um teorema com nome difícil — Nyquist-Shannon — que diz o seguinte em português claro: para capturar uma frequência de X Hz, você precisa amostrar pelo menos a 2X Hz.

O ouvido humano ouve até ~20 kHz (na juventude; depois dos 30, uns 15-17 kHz é o topo real). Então para capturar tudo que o ouvido ouve, precisamos de pelo menos 40 kHz de amostragem.

Por que não 40 kHz exatos? Porque o filtro que "limpa" frequências acima do limite não é perfeito — ele precisa de uma margem. 44.1 e 48 kHz são essas margens, escolhidas por razões históricas diferentes (o 44.1 veio de gravação em fita de vídeo VHS que os engenheiros da Sony usavam para gravar áudio digital nos anos 70).

Regra prática para seus projetos

Use 48 kHz como padrão. É o padrão de vídeo, de broadcast, e o que sua interface USB vai rodar por default. Só mude para 44.1 kHz se for gravar especificamente para CD (raro hoje) ou se o hardware exigir.

Quanta memória isso consome?

Vamos fazer a conta. A 48 kHz, com áudio estéreo (2 canais) e 32 bits por amostra (4 bytes):

cálculoaritmética
48.000 amostras/s × 2 canais × 4 bytes = 384.000 bytes/s
                                      ≈ 375 KB/s
                                      ≈ 22 MB/minuto
                                      ≈ 1,3 GB/hora

Para uma mesa com 32 canais processados a 48 kHz / 32-bit float, o fluxo interno é ~6 MB/s. Pouco para um computador moderno. É por isso que uma CPU de mini-PC N100 dá conta de mixer digital — não é processamento pesado, é processamento constante e pontual no tempo. Voltamos nisso depois.

§ 04

Aliasing: quando o digital mente.

Consequência direta do Nyquist: se aparecer na entrada uma frequência mais alta que metade da sample rate, ela não some simplesmente. Ela reflete e aparece como uma frequência mais baixa, diferente da original.

Isso se chama aliasing. O nome vem de "apelido" — a frequência original se disfarça de outra.

Exemplo concreto: você está a 48 kHz (Nyquist = 24 kHz). Entra na interface um sinal ultrassônico de 30 kHz. Esse sinal aparece como se fosse 18 kHz. Contaminação pura.

Por isso toda interface de áudio séria tem um filtro anti-aliasing analógico antes do conversor A/D. Esse filtro corta tudo acima de ~22 kHz antes da amostragem acontecer. Interfaces baratas têm filtro ruim e podem deixar passar aliasing; interfaces profissionais têm filtro bem projetado.

Quando você vai encontrar isso na prática

Quando você gerar áudio por código — por exemplo, uma onda quadrada ou um oscilador digital para efeitos — esse sinal gerado pode ter harmônicos acima de Nyquist. Se você não filtrar, vai aparecer aliasing. Isso é problema de quem escreve sintetizadores e distorções, não tanto de quem só processa áudio vindo do microfone. Mas é bom saber.

§ 05

Quantização: a régua que mede o som.

Sample rate resolve "com que frequência medir". Quantização resolve "com que precisão medir cada valor".

Quando a interface mede a tensão elétrica no microfone, ela precisa converter esse número analógico (infinitamente preciso) em um número digital com precisão finita. Quanto mais bits você usa para representar cada amostra, mais preciso o número.

Os bit depths que importam

Bit depth Valores possíveis Dynamic range teórico Onde é usado
16-bit int 65.536 96 dB CD, MP3, streaming
24-bit int 16.777.216 144 dB Gravação pro, conversores A/D
32-bit float ~4.3 bilhões (com range enorme) ~1528 dB DAW interno, DSP, processamento
64-bit float (absurdo, nunca falta) (astronômico) Mastering paranoico

"Dynamic range" é a diferença entre o som mais alto que você consegue representar sem clipar e o ruído de fundo que a própria digitalização produz. Para referência: a diferença entre um sussurro e um show de rock é ~80 dB. 96 dB de 16-bit int cobre isso, mas com pouca margem. 24-bit int cobre com folga enorme.

Por que 32-bit float é o rei do processamento

Enquanto áudio está sendo gravado ou tocado, 24-bit int é suficiente. Mas enquanto áudio está sendo processado — somado, multiplicado, filtrado — você quer 32-bit float. Razões:

  1. Não clipa internamente. 32-bit float suporta valores acima de 1.0 e abaixo de -1.0 sem estourar. Você pode somar 100 canais cheios e a matemática não quebra. Só precisa normalizar no final.
  2. Matemática rápida em CPU moderna. Processadores têm unidades SIMD (SSE, AVX, NEON) otimizadas para float32. Int24 não existe como tipo nativo — você tem que emular com int32.
  3. Range dinâmico gigante. Ruído de quantização fica muito abaixo de qualquer coisa audível.
Regra prática

Você vai processar áudio em f32 (Rust) ou float (C). Sempre. Converte para int só na entrada/saída da interface de áudio. Todo o seu código de DSP trabalha com floats normalizados no range aproximado de -1.0 a +1.0, onde 0.0 é silêncio e 1.0 é o pico máximo de amplitude.

§ 06

Float, int, PCM: os formatos.

Algumas siglas que você vai ver constantemente:

PCM — Pulse Code Modulation

É o nome técnico para "áudio digital não comprimido". Quando você vê PCM 16-bit ou PCM 24-bit, significa: amostras armazenadas como inteiros, uma atrás da outra, sem compressão. WAV é PCM. AIFF é PCM. MP3 não é PCM (é comprimido).

L16 e L24

Dentro do AES67 e do RTP, você vê L16 e L24. Significa "linear PCM 16-bit" e "linear PCM 24-bit" em formato big-endian. "Linear" porque é PCM direto, sem compressão não-linear como a-law/mu-law usada em telefonia.

Interleaved vs planar

Áudio estéreo tem dois canais. Como você guarda eles na memória?

dois layoutsvisualização
// Interleaved (intercalado): canais alternados
[L0, R0, L1, R1, L2, R2, L3, R3, ...]

// Planar: cada canal num buffer separado
[L0, L1, L2, L3, ...]
[R0, R1, R2, R3, ...]

WAV e a maioria das APIs de hardware usam interleaved. Engines de DSP frequentemente preferem planar, porque processar um canal de cada vez é mais eficiente em cache. Você vai converter entre os dois com frequência. Acostume-se.

§ 07
Experimento prático

Gerar uma senóide e salvar em WAV.

Objetivo: provar, mexendo com as próprias mãos, que áudio digital é "só" uma lista de números. Vamos gerar uma onda senoidal de 440 Hz (a nota Lá central de afinação), salvar como WAV, e tocar no player do sistema.

Passo 1 — Criar o projeto

terminalbash
cargo new modulo01-senoide
cd modulo01-senoide

Passo 2 — Adicionar a crate hound para escrever WAV

Edite Cargo.toml e adicione na seção [dependencies]:

Cargo.tomltoml
[dependencies]
hound = "3.5"

Passo 3 — Escrever o código

Substitua o conteúdo de src/main.rs por:

src/main.rsrust
use hound::{WavSpec, WavWriter, SampleFormat};
use std::f32::consts::PI;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let sample_rate: u32 = 48_000;
    let duration_seconds: f32 = 2.0;
    let frequency: f32 = 440.0;
    let amplitude: f32 = 0.5;

    let total_samples = (sample_rate as f32 * duration_seconds) as u32;

    let spec = WavSpec {
        channels: 1,
        sample_rate,
        bits_per_sample: 32,
        sample_format: SampleFormat::Float,
    };

    let mut writer = WavWriter::create("senoide_440hz.wav", spec)?;

    for n in 0..total_samples {
        let t = n as f32 / sample_rate as f32;
        let sample = amplitude * (2.0 * PI * frequency * t).sin();
        writer.write_sample(sample)?;
    }

    writer.finalize()?;
    println!("Gerei {} amostras em senoide_440hz.wav", total_samples);
    Ok(())
}

Passo 4 — Rodar e ouvir

terminalbash
cargo run

Vai aparecer um arquivo senoide_440hz.wav na pasta do projeto. Dê duplo-clique e escute. Você acabou de gerar áudio a partir de matemática pura, sem gravar nada.

Passo 5 — Experimentar

Agora mexa nos parâmetros e rode de novo: mude frequency para 880.0 (oitava acima), 110.0 (duas oitavas abaixo), amplitude para 0.1 ou 1.5 (cuidado com clip). Tente sample_rate = 8_000 — qualidade de telefone.

Checklist do que você aprendeu ao rodar isso

Você sabe agora: (1) o que é sample rate na prática, (2) que áudio digital é uma sequência de f32, (3) o que significa amplitude entre -1.0 e 1.0, (4) como usar crates externas no Rust, (5) como escrever um loop que gera dados e um writer que persiste em disco.

Glossário rápido
AMOSTRA (SAMPLE)
Uma única medição de amplitude. Num áudio de 48 kHz mono, tem 48.000 amostras por segundo.
SAMPLE RATE
Quantas amostras por segundo. Unidade: Hz ou kHz. Padrão profissional: 48 kHz.
BIT DEPTH
Quantos bits usados para representar o valor de cada amostra.
QUANTIZAÇÃO
O processo de arredondar um valor analógico contínuo para o valor digital mais próximo disponível dado o bit depth.
NYQUIST
Metade da sample rate. Frequência máxima que o sinal digital consegue representar sem ambiguidade.
ALIASING
Quando frequências acima de Nyquist aparecem como frequências diferentes mais baixas no sinal digital.
PCM
Pulse Code Modulation. Áudio digital não comprimido armazenado como inteiros amostra-por-amostra.
L16 / L24
Formatos PCM usados em RTP/AES67. Linear 16-bit e 24-bit big-endian.
INTERLEAVED
Layout de memória onde canais alternam: L, R, L, R, L, R...
PLANAR
Layout de memória onde cada canal tem seu buffer separado.
CLIP
Quando a amostra excede o valor máximo representável e é cortada. Distorção feia.
HEADROOM
Margem entre o nível nominal do sinal e o ponto de clip.
